# Round 1 — Build, Quality & Test Architecture

Author role: build / quality / test architect. Status: proposal for discussion (2026-10-28).
Library names below are placeholders; they follow whatever layering the core architect settles on.
The one thing this proposal does fix is that each layer is its own target, so layering is checked at link time.

**Library targets** (all `STATIC`, alias `kestrel::<lib>`, one directory each). Allowed dependencies go downward only:

| Target | Qt modules | Contents |
|---|---|---|
| `kestrel_base` | Core | Result/Error, strong ids, logging categories, assertions |
| `kestrel_knx` | Core | **sans-I/O** protocol: cEMI, KNXnet/IP frame codecs, DPT codecs, transport/tunnel state machines driven by `feed(bytes)` / `tick(now)` |
| `kestrel_model` | Core | project, places, topology, GA, undo commands (QUndoStack lives in Gui, so undo goes through our own command stack) |
| `kestrel_formats` | Core, Xml | native format, `.knxproj` / `.knxprod` import (zip via a vendored minizip-ng or QZip-like helper — the core architect decides) |
| `kestrel_bus` | Core, Network | UDP transports and discovery that wrap `kestrel_knx` state machines |
| `kestrel_sim` | Core, Network | simulated KNXnet/IP server, virtual TP line, simulated devices (memory, prog-mode, fault injection) |
| `kestrel_app` | Core | application services and commands (open, import, validate, program IA, download) shared by the GUI and CLI |
| `kestrel_ui` | Widgets, Quick, QuickWidgets, Qml, QuickControls2 | main window, docks, view-models, QML module `Kestrel.Ui` |

Executables: `kestrel` (ui+app), `kestrel-cli` (app only — **must not link Widgets**, enforced by a CMake check
on `LINK_LIBRARIES`), `kestrel-sim` (sim only). An NFR-3 guard test configures a fake consumer that
links only `kestrel_app` and fails if `Qt6::Gui` appears in the link closure.

**Compile options as INTERFACE targets** (never global `add_compile_options`):
- `kestrel_options`: `cxx_std_20`, `CXX_EXTENSIONS OFF`, `QT_NO_CAST_FROM_ASCII`, `QT_NO_CAST_TO_ASCII`,
  `QT_NO_KEYWORDS` (use `Q_SIGNALS/Q_EMIT`), `QT_DISABLE_DEPRECATED_UP_TO=0x060800`, `QT_NO_NARROWING_CONVERSIONS_IN_CONNECT`.
- `kestrel_warnings`. GCC/Clang: `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion
  -Wnon-virtual-dtor -Wold-style-cast -Woverloaded-virtual -Wcast-align -Wnull-dereference -Wdouble-promotion
  -Wformat=2 -Wimplicit-fallthrough`. GCC adds `-Wduplicated-cond -Wduplicated-branches -Wlogical-op`. MSVC: `/W4 /permissive- /utf-8
  /Zc:__cplusplus /Zc:preprocessor`. `-Werror` only through `KESTREL_WARNINGS_AS_ERRORS` (ON in CI and in dev presets,
  OFF by default so distro packagers on a newer compiler are not broken). `-Wconversion` is non-negotiable for protocol code. It
  is the cheapest defence against byte-level bugs in frames and memory addresses.
- `kestrel_sanitizers`: populated from `KESTREL_SANITIZE=address;undefined` (`-fsanitize=… -fno-omit-frame-pointer
  -fno-sanitize-recover=undefined`). Linked by everything, including tests and apps.

Top level: `cmake_minimum_required(VERSION 3.24)`, `find_package(Qt6 6.5 REQUIRED COMPONENTS …)`,
`qt_standard_project_setup(REQUIRES 6.5)` (AUTOMOC, GNUInstallDirs, policies), plus `qt_policy(SET QTP0001 NEW)`
for `qt_add_qml_module` resource paths. Qt modules come in through `QT_*` targets for each library, never through one blanket list.

**CMakePresets.json** (version 6). Hidden `base`: Ninja, `build/${presetName}`, `CMAKE_EXPORT_COMPILE_COMMANDS=ON`,
`CMAKE_COMPILE_WARNING_AS_ERROR` left OFF (we use our own option). Visible presets:
`debug` (gcc, Debug), `debug-clang`, `release` (RelWithDebInfo, gcc), `asan` (clang, Debug, `KESTREL_SANITIZE=address;undefined`),
`coverage` (gcc, Debug, `--coverage`, plus a `coverage` target running lcov/genhtml — `gcovr` is not installed, lcov is), `tsan` (optional
and allowed to be noisy, because Qt is not instrumented). The matching `testPresets` set `output.outputOnFailure`, and `asan` excludes label `death`.
`workflowPresets`: `ci-debug`, `ci-asan` (configure → build → test).

**CTest integration** lives in `cmake/KestrelTesting.cmake`, using four helpers that also set labels, timeout and environment:
- `kestrel_add_unit_test(<lib> SOURCES … LIBS …)` builds `unit_<lib>`. ctest name `unit.<lib>`, labels `unit;<lib>`, timeout 60 s.
- `kestrel_add_qt_test(<lib> <Class>)` builds `tst_<class>`. ctest name `qt.<lib>.<Class>`, labels `qt;<lib>`, env `QT_QPA_PLATFORM=offscreen`,
  args `-o <bin>/junit/<name>.xml,junitxml -o -,txt`.
- `kestrel_add_qml_test(<dir>)` uses `quick_test_main_with_setup` and `QUICK_TEST_SOURCE_DIR`. ctest name `qml.<dir>`, labels `qml;gui`.
- `kestrel_add_robot_suite(<name>)` runs `${Python3_EXECUTABLE} -m robot --outputdir … --variable CLI:$<TARGET_FILE:kestrel-cli>
  --variable SIM:$<TARGET_FILE:kestrel-sim> tests/robot/suites/<name>.robot`. ctest name `robot.<name>`, labels `robot;acceptance`, timeout 300 s,
  `DEPENDS`/`FIXTURES_REQUIRED` on the build of both executables.
Extra labels: `death`, `network` (localhost UDP), `multicast` (with `RESOURCE_LOCK knx_multicast`), `perf`, `slow`, and `hil`
(real hardware, never registered unless `KESTREL_HIL=ON`). `BUILD_TESTING` defaults ON at top level and OFF when Kestrel is used as a subproject.

## 2. UnitTests.hpp: placement and usage rules

**Placement:** `git mv UnitTests.hpp third_party/escain_unittests/` with its MIT LICENSE and a `VERSION` file holding the upstream commit.
It becomes an INTERFACE target `escain::unittests` with a `SYSTEM` include. It is a vendored dependency even though the
author owns it. Fixes go upstream first and are then re-vendored, never edited in place.
`tests/support/unit_main.cpp` (`#define ESCAIN_DEFINE_MAIN` + include) is an OBJECT library `kestrel_unit_main` linked into every
unit binary. That gives exactly one `main` (it is the `test_main.cpp` the header expects).

**Organisation:** **one unit binary per library** (`unit_knx`, `unit_model`, …) with `<Class>_test.cpp` files. It gives fast linking, the
binary maps onto the layer, and `-f=` selects within it. Death tests go in a separate binary, `death_<lib>` (label `death`), for three reasons:
`MUST_DIE` uses `signal()`+`setjmp/longjmp`. That fights ASan's own SEGV handler, skips destructors (LSan noise) and is
process-global (not thread-safe). These binaries are built only when assertions are active (Debug). They get `-Wno-clobbered` on GCC,
because the header's pragma covers only `main`, and `MUST_DIE` inside a test body can trigger `-Wclobbered`.

**Constraints observed in the header, and the resulting team rules:**
1. `ASSERT*`/`MUST_*` expand to `setFail(); return;`, so they work only inside a `UNIT_TEST` body, never in helpers.
   Helpers return `bool`/`std::string` diagnostics, and the body asserts on them.
2. `ASSERT`/`ASSERT_FALSE` are a bare `if` (dangling-`else` hazard), so braces are mandatory around them in any `if/else`. clang-tidy's
   `readability-braces-around-statements` enforces this.
3. `ASSERT_EQ(a,b)` does `auto aVal=a; decltype(aVal) bVal=b;`:
   - **actual first, expected second**. `ASSERT_EQ("abc", s)` compares *pointers*, so a literal must never be the first argument.
   - `b` is converted to `a`'s type. `ASSERT_EQ(u8, 300)` silently truncates, but `-Wconversion` catches it, which is one more reason to keep it.
   - `uint8_t` prints as a char, which is unreadable for KNX bytes. Compare bytes through `kestrel::Bytes`/`QByteArray`, which have hex printers,
     or cast to `int`.
   - Both types need `operator<<(std::ostream&, T)`. Rule: **every core value type** (`IndividualAddress`, `GroupAddress`, `Dpt`,
     `Error`, enums through a `toString()`) gets an `operator<<` in its own namespace, found by ADL. That also helps logging and debugging.
4. `tests/support/QtPrinters.hpp` defines `operator<<` for `QString`, `QByteArray` (hex), `QStringList`, `QVariant`, `QDateTime`
   in the **global** namespace (Qt types live there, so ADL finds them). `tests/support/Printers.hpp` adds `std::optional`, `std::vector`,
   `std::pair` and `std::chrono` templates. Because those templates are in the global namespace, they are found only by ordinary lookup.
   So `UNIT_TEST`s are written at file scope, never inside a namespace that declares its own `operator<<` (it would hide them).
5. Test names are struct names at file scope. A duplicate name inside a binary gives a link error on `X::run`, which is good, so the names
   carry the requirement ID (see §4).
6. The header defines global names (`TEST`, `Registry`, `GET_MACRO`, `PLATFORM_UNIX`, `detail`). Include it **last**, only in test TUs,
   and never in the same TU as `<QTest>`.
7. MSVC risk: `__try` in a function with unwindable objects (C2712) may need `/EHa` for death binaries. Verify this at the Windows milestone.

**When to use Qt Test instead:** if the code under test needs an event loop, `QSignalSpy`, timers, sockets, `QTRY_*`, or a
`Q(Core|Gui)Application`, use Qt Test (`QTEST_GUILESS_MAIN` for bus/sim, `QTEST_MAIN` with offscreen for widgets). Plain use of `QString`
or `QByteArray` stays in UnitTests. Because `kestrel_knx` is sans-I/O, almost all protocol logic is unit-testable without an event loop:
time is injected (`tick(steady_clock::time_point)`), not read. QML components are tested with Qt Quick Test against mock view-models.

**Upstream wishes for UnitTests.hpp (non-blocking, the author owns it):**
- `--list`, so CMake can discover single tests like `gtest_discover_tests`, giving one ctest entry and label per test.
- `--junit=<file>` for CI reports.
- An exact-match or exclude filter (`-f=` is a substring match).
- `NO_COLOR` support (escape codes clutter CI logs).

## 3. Robot Framework strategy

Robot 7.4.2 is installed and its builtins `Process`, `OperatingSystem`, `String`, `Collections` and `XML` are available, so no
extra Python dependency is needed for phase 1.

| Option | Pros | Cons |
|---|---|---|
| (a) `kestrel-cli` + `kestrel-sim` | deterministic, headless, fast, runs in any CI container, exercises real UDP framing | does not cover GUI wiring |
| (b) GUI automation server | covers docks, QML, dialogs | needs a display/offscreen, is flaky and slow, adds an attack surface, needs a Python client |
| (c) both | full coverage | cost of (b) |

**Recommendation: (c), staged. (a) is the backbone from milestone 1. (b) comes later, as a thin set of GUI smoke suites.** This works because
the GUI and the CLI call the same `kestrel_app` services, so workflow correctness is proven once through the CLI and the GUI suites
only prove wiring.

**System under test (a):** `kestrel-cli` with subcommands that are stateless across invocations (the project file is the state), and
`--json` for machine-readable output and stable exit codes (0 ok, 1 validation findings, 2 usage, 3 I/O, 4 bus error).
Examples: `project new`, `import knxproj`, `validate`, `topology add-device`, `ga add`, `link`,
`bus discover`, `device info`, `device program-ia`, `device download [--partial=params|tables]`, `group write|read`, `monitor --count N`.

**`kestrel-sim`** is a thin executable over `kestrel_sim`. That library is also used *in-process* by Qt tests through a loopback transport.
- It binds `--port 0` and prints `{"event":"ready","port":N}` on stdout. Ephemeral ports mean parallel ctest runs do not collide.
- It loads a JSON scenario: interface IA, devices (IA, mask version, manufacturer, memory size, prog-mode), and faults (drop the Nth ACK, delay,
  reject the connect, sequence errors).
- It takes JSON-lines commands on stdin: `press-prog-button 1.1.5`, `dump-memory 1.1.5 0x4000 32`, `telegram-log`, `set-fault …`, `quit`.
  Events go to stdout (every telegram as JSON). Routing/multicast scenarios get label `multicast` and a resource lock.

**Python libraries** (`tests/robot/libraries/`, `ROBOT_LIBRARY_SCOPE = "SUITE"`, typed keywords, about 150 lines each):
- `KestrelCli.py` has `Run Kestrel    *args` (returns parsed JSON, keeps rc/stderr), `Kestrel Should Succeed`, `Create Project`,
  `Import Knxproj`, `Validation Should Report    code`, `Program Individual Address    ia`, `Download Device    ia    partial=`,
  `Group Write    ga    dpt    value`.
- `KestrelSim.py` has `Start Simulator    scenario` (subprocess, waits for `ready`, exposes `${SIM_URL}`), `Press Programming Button    ia`,
  `Device Memory Should Be    ia    addr    hex`, `Device Should Have Individual Address`, `Simulator Should Have Seen Group Write    ga    hex`,
  `Inject Fault    …`, `Stop Simulator` (teardown, which attaches the telegram log to the Robot log).
- `KestrelGui.py` (phase 2) talks to a `QLocalServer` automation endpoint. It is compiled only with `KESTREL_ENABLE_AUTOMATION=ON`
  (never in release packages) and enabled only by `--automation=<socket-name>`. The protocol is JSON-lines `{id,cmd,args}` with
  `invoke-action <objectName>`, `find-item <dock>/<objectName path>`, `get/set-property`, `wait-until`, `screenshot`. Keywords include
  `Start Kestrel Gui`, `Trigger Action`, `Item Property Should Be`, `Capture Dock`.

## 4. Traceability

- **Robot:** a tag equal to the ID (`FR-COM-1`, `NFR-5`). Multiple tags are allowed. `robot --include FR-COM*` runs a feature area.
- **UnitTests:** `UNIT_TEST(FR_GA_1__parsesThreeLevelAddress)`. The double underscore terminates the ID, so `-f=FR_GA_1__` does not match
  `FR_GA_10`. Tests without a requirement use `<Class>_<behaviour>`.
- **Qt Test:** private slot `fr_bus_2__reconnectsAfterHeartbeatLoss()`. **QML:** `function test_FR_DEV_1__enumParameterShowsChoices()`.
- **`tools/trace.py`** scans `tests/**` by regex, collects Robot tags via `robot.api.TestSuiteBuilder`, parses the IDs in
  `01-requirements.md`, and generates `build/traceability.{md,json}`. It never needs hand maintenance. CI fails on tests that reference an
  unknown ID. Requirements with no tests are reported, and become an error once the requirement's milestone is marked done.

**`specs/05-test-strategy.md` outline:**
1. Scope and principles: the test pyramid, determinism, no hardware in CI (NFR-5).
2. Levels and tools: a decision table (UnitTests / Qt Test / Qt Quick Test / Robot / manual HIL).
3. Test-data policy: synthetic fixtures generated by `tools/fixtures` (clean-room). An optional private corpus is read from
   `KESTREL_PRIVATE_CORPUS` (label `private-corpus`, skipped when unset, never committed).
4. Simulator specification: scenario schema, fault model, control protocol.
5. Naming, tagging, labels, and how to run subsets (`ctest -L unit`, `-f=`, `robot --include`).
6. Traceability matrix: links to the generated artifact and the rules enforced by `trace.py`.
7. Coverage: `kestrel_knx` ≥ 90 % lines, other core libraries ≥ 80 %, no gate on `kestrel_ui`. Reported per library.
8. Sanitizers, fuzzing (libFuzzer harnesses on frame and XML parsers, later) and perf tests for NFR-8 (generated 1k devices / 10k GAs, label `perf`).
9. CI gates and the flaky-test policy (quarantine label `flaky` with an issue link, max 2 weeks).
10. Manual hardware-in-the-loop checklist: real IP interface/router, programming flow, per release.

## 6. Coding conventions

- **Style is derived from the author's own `UnitTests.hpp`:** tabs for indentation, Allman braces, `PascalCase` types, `camelCase` functions
  (`getName`, `isPassed`), `m_` members, `k`-prefixed constants (`kDefaultPort`), and `UPPER_CASE` only for macros (prefix `KESTREL_`).
  Namespaces `kestrel::<lib>`. Files `PascalCase.hpp/.cpp` matching the main class. Tests `<Class>_test.cpp` and `tst_<class>.cpp`.
  `.clang-format`: `BreakBeforeBraces: Allman`, `UseTab: ForIndentation`, `IndentWidth/TabWidth: 4`, `ColumnLimit: 120`.
- **Header layout:** `#pragma once`, then includes grouped own → kestrel → Qt → std (clang-format `IncludeBlocks: Regroup`). Public headers
  live in `include/kestrel/<lib>/`, so a library cannot include a layer it does not link. Every header compiles standalone, checked by a
  generated `header_check` TU for each header in CI.
- **Error handling (C++20, so no `std::expected`):**
  - **Expected failures** are returned as `kestrel::Result<T>` = `tl::expected<T, kestrel::Error>`. That is a vendored single header (CC0),
    aliased in `kestrel_base`, so moving to C++23 `std::expected` is a one-line change. Expected failures are user files, malformed frames,
    bus timeouts, NAKs and validation. `Error` carries `{ErrorCode code; QString message; QList<QString> context}` and has `operator<<`.
  - **Contract violations** (programmer bugs) use `KESTREL_ASSERT(cond)`. It maps to `Q_ASSERT_X` in debug and is tested with `MUST_DIE`.
  - **Exceptions** are allowed only *inside* a library implementation, such as deep XML parsing, and must be converted to `Result` at
    the public API boundary. They must never escape into a Qt slot or the event loop, or through `QFuture` continuations.
    `MUST_THROW` is therefore used only on internal parser tests.
  - Asynchronous bus operations report `Result` through signals or `QFuture<Result<T>>`. They never block the GUI thread (NFR-7).
- **Logging:** each library declares its categories in `Logging.hpp` (`Q_DECLARE_LOGGING_CATEGORY`): `kestrel.knx.frame`,
  `kestrel.bus.tunnel`, `kestrel.bus.telegram`, `kestrel.formats.knxproj`, `kestrel.sim`. Debug output is off by default.
  `kestrel-cli --log "kestrel.bus.*=true"` maps to `QLoggingCategory::setFilterRules`. Robot suites enable `kestrel.bus.telegram`
  and attach it to failing tests. No `qDebug()` without a category (clang-tidy custom check or grep in `lint`).
- **Value types:** addresses, DPT values and frames are regular value types with `operator<=>`, `operator<<` and
  `static Result<T> parse(QStringView)`. That makes them assertable, loggable and fuzzable. `QObject` is used only where signals are needed.
- **Strings:** `QString` in the model and UI, `QByteArray`/`std::span<const std::byte>` for wire data. String literals use `u"…"_s`, because `QT_NO_CAST_FROM_ASCII`
  forces it. That also keeps `ASSERT_EQ(qstr, u"x"_s)` type-exact.

## My 3 non-negotiable decisions

1. **The protocol layer is sans-I/O and the simulator is first-class.** `kestrel_knx` never touches sockets or clocks, and
   `kestrel_sim` (in-process and as the `kestrel-sim` process) is built from day one next to the real transport. That is what makes NFR-5 and NFR-7 testable.
2. **Robot acceptance tests drive `kestrel-cli` against `kestrel-sim` first.** GUI automation comes later, opt-in and thin. Both front-ends
   call the same `kestrel_app` services, so the CLI suites prove the workflows.
3. **Enforced gates from the first commit:** `-Wall -Wextra -Wpedantic -Wconversion` with `-Werror` in CI, ASan+UBSan on every PR, clang-format and
   the forbidden-proprietary-files hook in pre-commit, and requirement IDs in test names/tags checked by `trace.py`.
