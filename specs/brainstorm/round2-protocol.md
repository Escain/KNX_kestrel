# Brainstorm R2: protocol architect, reply to UI / model / quality

> **Superseded on this point:** the `tl::expected` ruling in §2 was a late correction made after ADR-004 was
> accepted and M1 was built on the own `Result<T>`. ADR-004 stands; see its "Considered later" note.

Facts checked on the dev box:
- No zip headers: `libminizip.so.1` is installed, but only the runtime of zlib's old minizip 1.x, with no headers and no AES. No libzip or quazip.
- `tl/expected.hpp` is not in `/usr/include`, but offline copies exist (Qt Creator, KiCAD trees).
- Present: zlib, libdeflate, zstd, sqlite3 and OpenSSL 3.5.

## 1. Endorsed as-is
- **Model.** I endorse these points:
  - Value-type entities and Kestrel ids.
  - Parameter values as canonical strings, typed through the catalog `ParameterType`.
  - Links as a relation table with the sending GA at `order 0`. That is exactly the input the table builders need.
  - "Needs download" derived from a hash, not stored.
  - Embedded MasterData and application programs, so the mask `Resources` and `LdCtrl` lists are available at download time on any machine.
  - Diagnostics instead of exceptions on import.
- **Quality.** I endorse these points:
  - Sans-I/O `kestrel_knx` with time injected through `tick(steady_clock::time_point)`. I adopt that name and drop my `IClock`.
  - `-Wconversion` with `-Werror`.
  - `kestrel-sim` on `--port 0`, printing `{"event":"ready"}`, with JSON-lines control on stdin. This replaces my separate TCP control port.
  - The forbidden-files hook.
  - Libfuzzer on frame parsers.
- **UI.**
  - The SPSC ring plus a 20–30 Hz drain for the group monitor.
  - A single `BusSession` service. Its core part must live below `viewmodels` (see 3c).

## 2. Conflicts and rulings
| Tension | Ruling | Why |
|---|---|---|
| Qt-free core vs QtCore in core | **Split by layer.** `kestrel_knx` (codecs, TL/AL/KNXnet/IP state machines, DPT codecs, sim device core) is **std-only**. `kestrel_base`, model, catalog, persist and ets may use **QtCore only**. QtNetwork appears only in `kestrel_bus` and `kestrel_sim_net`. | Protocol code is bytes and timers, so Qt buys nothing there. Std-only keeps fuzz harnesses and the sim core tiny. The model genuinely benefits from `QString`, `QXmlStreamReader`, `QJsonDocument` and `QSaveFile`. |
| `kestrel_knx` linking QtCore (quality table) | It does not. Logging goes through a std `LogSink` callback, which `kestrel_bus` routes to `QLoggingCategory` (`kestrel.knx.frame`, …). | This keeps the rule above enforceable by the CMake link check. |
| minizip-ng (FetchContent) vs own ZIP | **Own `kestrel_archive`**, with zlib/libdeflate for inflate and deflate. It reads and writes store/deflate entries, reads ZIP64 and does **WinZip-AES** decryption: PBKDF2-HMAC-SHA1 with 1000 iterations, AES-CTR with a *little-endian* counter (hand-rolled over OpenSSL AES-ECB), HMAC-SHA1-80 and a 2-byte password verifier. That is about 800 lines, fuzzed, with test vectors generated by `7z`/`zip` where available. The `ZipReader` interface stays stable so minizip-ng can be dropped in later. | FetchContent fails offline. We need byte-deterministic *writes* for `.kestrel` anyway. The ETS-specific key derivation (PBKDF2-SHA256 for schema ≥ 21) is ours to write in either case. |
| Undo: History/Tx vs QUndoStack | **The model's `History` (Tx log) is the only source of truth.** If the UI wants a `QUndoStack`, it is a mirror (`UndoMirror`), never authoritative. | VM-built `Command`s would bypass `Tx`, which breaks ChangeSets, autosave and validation. |
| `tl::expected` vs own `Result<T>` | **Vendor `tl::expected`** (CC0, header-only, std-only) into `third_party/tl_expected/`. It is not in `/usr/include`, but offline copies exist locally (Qt Creator and KiCad both bundle it). Record the upstream version in `VERSION`. Alias it in a std-only `kestrel/base/Expected.hpp` that `kestrel_knx` can include too: `template<class T> using Result = tl::expected<T, Error>`. I withdraw my own-`Result` proposal. | It is available offline, battle-tested and std-only, and it is a drop-in for C++23 `std::expected`. Rule: use only the `std::expected` API subset (no `tl::`-only extras such as `map_error` spelling differences) so the C++23 switch stays an alias change. |
| `Error` with `QString` (quality) (applies to `tl::expected` as well) | `kestrel_knx` uses `knx::Error{ErrorCode code; uint16_t detail; /*e.g. NAK seq, KNXnet/IP status*/}`, a POD with an `operator<<`. `kestrel_bus` maps it to the QString-based `kestrel::Error` at the boundary. | Consequence of the std-only rule. |
| Sim placement (quality: Core + Network) | `kestrel_sim` (std-only: VirtualBus, VirtualDevice, LSMs, fault rules) plus `kestrel_sim_net` (QtNetwork KNXnet/IP server). The `kestrel-sim` executable links both. | Unit tests use the sim in-process with no event loop. |
| Robot example `Device Memory Should Be 1.1.5 0x4000 01 11 05 08 01` | Expected table bytes are **never hand-written in suites**. Use `Address Table Should Contain  1.1.5  1/0/1  1/0/2`, where the sim decodes with the same flavour builder from the mask resources (M112 table at 0x4000 = `[N+1][IA][GAs sorted]`). Raw-hex goldens live only in `unit_knx` table-builder tests. | Hand-written bytes are where spec mistakes hide. They also duplicate layout knowledge in Python. |
| Model rule GA-005 "sender = T or R flag" | The sender is a CO with **T** (transmit). R only answers reads. | Correctness. |

## 3. Missing pieces that will bite us
a. **Commissioning facts are not undoable edits.** "IA programmed", the serial read from the device, the downloaded image hashes and
   "device unloaded after failed download" all describe the physical world. They go through a separate
   `project.recordCommissioning(…)` channel. That channel emits a ChangeSet, marks the project dirty and is **excluded from History**.
   Otherwise Ctrl+Z after a download would make us lie about the device.
b. **Download works from a snapshot.** At start we freeze `{program shared_ptr, params, links, IA, MasterData}`, build the `DeviceImage`
   and plan on a worker thread, and execute on the bus thread. Edits made during a download simply make the device "needs download" again.
   Store **per-part hashes** (`iaHash`, `paramImageHash`, `tableHash`, `appHash`) so FR-COM-3 can choose the "par" or "grp" procedure automatically.
c. **One connection-oriented session per tunnel at a time.** A tunnel has one IA. Many interfaces have 1–4 tunnel slots. Bus monitor
   mode (`TUNNEL_BUSMONITOR`) is exclusive and cannot send. Therefore `kestrel_bus::BusSession` (std state, Qt I/O) owns:
   - an operation queue with serialised management ops;
   - group traffic interleaved between TL frames;
   - slot accounting.

   The UI's `OperationsPanel` only displays that queue. Downloading to N devices in parallel needs N tunnels. This is opt-in, later.
d. **The tunnel IA must not collide with project devices.** Add validation rule TOP-004 using the IA from the CONNECT_RESPONSE CRD,
   and warn before commissioning.
e. **Telegram store payloads.** Extended frames and Data Secure carry up to 254 bytes, so the 14-byte inline buffer needs an overflow arena.
   Note also that TP1 tops out at about 50 telegrams/s per line. Keep the 5000/s benchmark (routing aggregates lines), but realistic
   soak tests should use bursty TP-like traffic from the sim.
f. **The MasterData version matters for downloads.** The newest master is not always right for an old program. Store the
   `MasterData Version` that each embedded program came with, and resolve mask procedures against that version. If several exist, prefer the newest one
   that contains the mask. Add a corpus test that compares the resolved `DownloadPlan` across master versions.
g. **Synthetic fixtures need an owner and a schema.** `tools/fixtures` generates `test-master.xml` (DPT subset plus masks
   0705/07B0/091A written from the spec) and `M-FFFF` products. The protocol team owns the mask/LdCtrl part, and model/quality own the rest.
   This is milestone-0 work, because every download test depends on it.
h. **KNX Secure later implies key storage now.** Reserve opaque `secure` blobs in the device and project JSON (FDSK, tool key,
   sequence counters, IP Secure passwords). These must be **encrypted at rest** and never put in autosave in clear text. Decide the format before v1 freezes.
